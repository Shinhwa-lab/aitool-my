# d1_buyers_raw.xlsx 데이터 품질 진단 보고서

- 대상: `data/day1/d1_buyers_raw.xlsx` → `buyers` 시트 (원본은 수정하지 않음)
- 기준일: 2026-09-30 (`readme` 시트) · 열 정의: `data/data_dictionary.xlsx` → `columns` · `codes` · `payment_terms_map` 시트
- 진단 코드: `scripts/d1_quality_check.py` (읽기 전용) — 실행 `uv run python scripts/d1_quality_check.py`
- 셀 값은 openpyxl로 **변환 없이** 읽었다. 그래서 '유형'은 엑셀 셀에 실제로 저장된 유형(int · float · str · 빈칸)이다.
- **행 번호 = 엑셀 행 번호**(1행은 머리글, 데이터는 2~154행). 표 안의 `글자`는 셀 값을 글자 그대로 옮긴 것이다.
- 이 보고서는 **진단만** 한다. 처리 제안은 Day2 정제 때 사람이 정할 후보이고, 아직 고치는 코드는 없다.

**슬래시형 33셀의 일/월 순서**

| 구분 | 셀 수 | 의미 |
|---|---|---|
| 앞자리 > 12 (예 `29/04/2014`) | 18 | 앞자리가 '일'로 확정 → `DD/MM/YYYY` |
| 뒷자리 > 12 | 0 | `MM/DD/YYYY`로 확정되는 셀은 없음 |
| 둘 다 12 이하 (예 `01/06/2021` `10/11/2017` `03/12/2025`) | 15 | 형식만으로는 일/월 순서를 정할 수 없음 |

- `DD/MM/YYYY`로 읽는 근거: 확정 가능한 18셀이 모두 DD/MM이고, MM/DD로 확정되는 셀은 0개다.
  다만 한 열에 두 순서가 섞였을 가능성을 데이터만으로 배제할 수는 없다 → 모호한 15셀은 **확인 필요**.
- 4형식 모두를 위 규칙으로 읽으면 153셀 모두 날짜로 해석된다. 범위 2012-03-21 ~ 2026-03-02이고, 기준일(2026-09-30) 이후 날짜는 없다.
